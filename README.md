## Запуск проекта

Для запуска демонстрации работы выполните команду в терминале:

```
python3 -m src.main
```

- **Логи**: пишутся в файл `app.log` и дублируются в консоль.

Для запуска тестов (с проверкой покрытия):
```
pytest
```

## Реализованный функционал (по лабораторным)

### Лабораторная работа №1: Источники задач и контракты
Все источники задач (файлы, API, генераторы) не имеют общего базового класса, но реализуют единый поведенческий интерфейс с помощью `typing.Protocol` и `@runtime_checkable`. 
- **`TaskManager`** осуществляет строгую runtime-проверку объектов при добавлении.
- Источники возвращают данные итеративно (через `yield`), не перегружая оперативную память.

### Лабораторная работа №2: Модель задачи и дескрипторы
Доменная модель `Task` строго инкапсулирована:
- **Пользовательские дескрипторы**:
  - `IntDescriptor` — data-дескриптор, проверяющий тип и границы чисел (например, приоритет от 1 до 30).
  - `NonEmptyStr` — data-дескриптор, отсекающий пустые строки и пробелы (`strip`).
- **Свойства (`@property`)**: вычисляемые свойства `created_at` (только чтение) и `is_urgent` (приоритет > 10).
- При нарушении инвариантов генерируются кастомные ошибки из `src.common.exeptions` (например, `ValidationError`).

### Лабораторная работа №3: Очередь задач (Итераторы и генераторы)
В `src/queue.py` реализован класс пользовательской коллекции `TaskQueue`:
1. **Собственная структура данных (Priority Queue)**: 
   Вместо использования стандартного модуля `heapq`, внутри очереди реализована собственная куча (методы `_heapify_up`, `_heapify_down`, `_heap_push`, `_heap_pop`). Алгоритм Min-Heap адаптирован под Max-Heap через инверсию приоритетов.
2. **FIFO при равных приоритетах**: 
   Для задач с одинаковым приоритетом реализован строгий порядок FIFO (кто первый пришел, тот первый ушел) с помощью счетчика `itertools.count()`. Это также предотвращает ошибку сравнения объектов `Task` между собой.
3. **Ленивая обработка**: 
   Очередь читает источники и отдает данные лениво через `yield`. Реализованы методы потоковой фильтрации (`filter_by_status`, `filter_by_priority`), которые сохраняют сортировку по приоритету и не создают промежуточных списков в памяти.
4. **Поддержка стандартных конструкций Python**: 
   Очередь поддерживает многократный обход циклом `for`, конвертацию в `list()` и корректно обрабатывает `StopIteration`.
5. **Магические методы сложения**: 
   Модель `Task` реализует методы `__add__` и `__radd__`, что позволяет применять стандартную функцию Python `sum(queue)` ко всей очереди задач. Результатом является единичная задача с объединенным описанием и максимальным приоритетом.
